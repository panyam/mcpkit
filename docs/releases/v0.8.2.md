# v0.8.2

A patch release that brings mcpkit's protocol types in line with the MCP
schema, field for field. The headline fix is `instructions`, which mcpkit
sent inside `serverInfo` since the first week of the repo, where no
spec-following host looks for it. The rest is the same kind of audit applied
to the other types: identity, list primitives and content blocks gain the
fields the schema defines, and lose three it never did. There is also a fix
for a v1 tasks hang that showed up as an intermittent CI failure.

Some of this breaks compilation for callers of removed fields and helpers.
As far as we can find, nothing outside mcpkit's own tests used them, so it
rides a patch per `RELEASING.md`'s pre-1.0 note.

## Breaking

- **`core.ServerInfo.Instructions` is gone; use `server.WithInstructions`.**
  (PR 1561, issue 1560)

  ```go
  // before
  server.NewServer(core.ServerInfo{Name: "demo", Version: "1.0", Instructions: text})
  // after
  server.NewServer(core.Implementation{Name: "demo", Version: "1.0"},
      server.WithInstructions(text))
  ```

- **`PromptDef.Annotations` and `Server.RegisterExperimental{Tool,Resource,Prompt}`
  are removed.** No schema gives `Prompt` an `annotations` field, and
  `experimental` is not one of the keys the spec defines for tool or resource
  annotations. (PR 1565, issues 1562 and 1566)
- **`PromptArgument.Schema` is no longer sent to clients.** It is still
  server-side config, and the dispatcher still validates `prompts/get`
  arguments against it. `prompts/list` just omits it now, since no schema
  defines it there. (PR 1565)
- **`stateless.Backend` gains `Instructions() string`**, for anyone
  implementing it outside mcpkit. (PR 1561)
- **`ext/ui`: `DownloadFileRequest.Contents` is `[]core.Content`** instead of
  raw JSON. (PR 1565)

## Fixed

- **`instructions` reaches hosts.** Every schema since 2025-03-26 puts it on
  `InitializeResult`, beside `serverInfo`, and the 2026-07-28 draft puts it on
  `DiscoverResult` too. mcpkit nested it inside `serverInfo` on initialize,
  left it out of `server/discover`, and repeated it in the `_meta` serverInfo
  of every stateless result. The TypeScript SDK's `getInstructions()`
  returned `null` against v0.8.1 and returns the text now. The client reads
  it into `Client.Instructions` on both wires. (PR 1561)
- **v1 `tasks/result` no longer hangs** when a task elicits, or finishes, in
  the gap between the handler's last check and its wait. A side-channel
  request is a channel send rather than a store update, so nothing woke the
  handler and the tool blocked forever on the reply. This was the
  intermittent `TestTaskElicitE2E` failure (issue 390). (PR 1561)
- **The stateless `_meta` clientInfo sends the client's whole identity.** It
  was built from name and version only. (PR 1561)

## Changed

- **`core.Implementation` is the one identity type**, as in the spec, with
  `ServerInfo` and `ClientInfo` kept as aliases. Client identity gains
  `title`, `description`, `websiteUrl` and `icons`, and both sides gain
  `icons` (`core.Icon`). (PR 1561)
- **List primitives carry the schema's fields.** `icons` on tools, resources,
  resource templates and prompts. `size` on resources. `_meta` on resources,
  templates and prompts. `title` on prompt arguments. Resource-level `_meta`
  (`core.ResourceMeta`, for MCP Apps `ui`) could not be set at all before.
  Every new field is omitted when unset. (PR 1565)
- **Content blocks gain `annotations`, `_meta` and `resource_link`.**
  `core.ResourceLinkContent(def)` builds a link. `Content`'s decoder now
  reads every field the struct has; it used to copy fields by name, so it
  would have dropped all of these on the client. (PR 1565)

## Security

- **`compression` 1.8.2** in the `ext/ui` Playwright test workspace, for
  GHSA-vc2v-76pw-4v95. Test tooling only; nothing shipped depends on it.
  (PR 1564)

## Upgrading downstream

- **declaire**: move `Instructions` out of `core.ServerInfo{...}` into
  `server.WithInstructions(...)`. That is what fixes declaire issue 308.
- **chakra**: a version bump only. chakra issue 76 tracks putting connected
  servers' instructions into its system prompt, which is newly possible.

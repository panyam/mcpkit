# v0.8.18

A patch release for the room bridge, so a host such as chakra can let any agent drive a web app's
own pages. A web app now mounts a relay, the bridge and a join endpoint in a few lines, and its
pages join with one call. Pages declare the events they emit, with a payload schema and a context
hint, and agents see them in `events/list`. The page wire is written down in `WIRE.md`. A new
example, Lanternfall, is a map game whose game master is an agent, and `make exercise-aipage`
plays it. Everything new is additive and lives in the experimental rooms modules.

## Upgrade notes

- **`experimental/ext/rooms/massrelay` requires massrelay v0.3.7.** Its `Signer` now wraps
  massrelay's `RelaySigner`. The `Signer` API is unchanged. (PR 1686)
- **`rooms-channel` subscribes to more event types.** After `attach` it listens to every room event
  type the bridge lists, including the ones pages declare, instead of the three built-in ones. A
  Claude Code session through it receives those events as channel messages too. (PR 1686)
- **A Go `rooms.Page` greets a bridge in a different order**: `page_state`, then `agents_allowed`,
  then `grants`, then `pairing_offer`, as the TypeScript page does. It no longer sends its label
  twice when focused. A bridge never depended on the order, and `WIRE.md` says none may. (PR 1686)

## Added

- **`rooms.JoinHandler`** answers a page's POST with its room, relay URL, a token scoped to that
  one room, the bridge subjects to trust, and the token's expiry. The host supplies `Subject` and
  `RoomOf` (401 and 403 on error) and a `TokenMinter`. (PR 1684)
- **`massrelay.NewLocal`** builds a relay that trusts its own `Signer`, with the bridge joined
  in-process, and `Local.JoinHandler` fills in the signer and the bridge subject. A web app mounts
  the relay, the bridge and the join endpoint in a few lines. (PR 1684)
- **`massrelay.Signer`** mints relay tokens whose `rooms` claim names one room, and its
  `Authenticator` accepts exactly those, also for a page's in-session refresh. (PR 1684)
- **`joinToolRoomFrom(endpoint)`** in `@panyam/mcpkit-rooms` joins through the join endpoint and
  trusts only the bridges it names. A new `getToken` option on `joinToolRoom` refreshes the relay
  token over the open connection, so the page keeps its id past the first token's expiry.
  (PR 1684)
- **Declared page events.** A page declares event types with `Page.DeclareEvent` or
  `registerEvent`, each with a payload schema and a context hint. The bridge validates each event
  emitted under a declared name, and tells the page why it dropped one with
  `notifications/rooms/event_refused`. `rooms.WithPageEventCatalog` fixes the types up front, as
  `WithPageTools` does for tools. (PR 1686)
- **roomsevents lists each declared type as its own SEP-3415 event type**, with the page's payload
  schema and its context hint under `_meta["io.github.panyam.mcpkit/context-hint"]`. The page's
  fields sit at the top level of the payload, beside `resource`, `page`, `user`, `label` and `at`,
  so a hint's template can name them. Types come and go with the pages that declare them, and each
  change announces `notifications/events/list_changed`. (PR 1686)
- **`rooms.Instructions`**, MCP server instructions text for a host to pass to
  `server.WithInstructions`. An agent with a fixed system prompt, such as Claude Code, learns
  attach, agreement, pairing codes and the event loop from it. (PR 1686)
- **`experimental/ext/rooms/WIRE.md`** documents the page wire: frames, every request and
  notification in each direction, the greeting, agreement and pairing, page events and their
  declarations, the join response and token claims, and versioning. `testdata/wire/page.jsonl` is
  its executable form, and the Go page and the TypeScript page both replay it. (PR 1686)
- **`examples/rooms/lanternfall`**, a map game in the player's own tab whose game master is an
  agent: Claude Code through `rooms-channel`, or a bundled LangGraph.js agent (`make gm`) that
  follows the declared context hints. An activity panel shows each event the page sends and each
  tool call an agent makes. (PR 1686, and follow-ups on main)
- **`make exercise-aipage`** runs Lanternfall three ways: a scripted MCP client driving a player's
  page in Chromium, the LangGraph game master when `ANTHROPIC_API_KEY` is set, and printed steps
  for Claude Code. CI runs the scripted check in the `rooms-aipage` job. (PR 1686)

## Changed

- **The `Signer` and the test relay mint through massrelay's `RelaySigner`** (massrelay v0.3.7),
  so the claim names come from the package that reads them. (PR 1686)

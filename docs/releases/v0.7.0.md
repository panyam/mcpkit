# v0.7.0

A minor release, eight days after v0.6.0. Fifty-seven PRs landed in that window,
plus four small commits made directly on main. Most of the work is in two
places: the MCP Events extension, which closed every divergence its new
conformance suite found, and MCP Apps, where the bridge JS now speaks the
`2026-01-26` wire protocol and the Go `AppHost` answers host requests itself.

The bump is a minor rather than a patch because two tagged modules break
behaviour on the wire. `experimental/ext/events` changes how webhooks are signed,
refuses callbacks it used to accept, and now verifies a webhook endpoint before
it will deliver to it. `ext/ui` changes the messages the bridge JS sends to its
host. Each is covered below with before and after values and a migration line.

**If you run an Events server with webhooks, read the Breaking section before
upgrading.** Three changes affect receivers you may not control:

- Signatures now key the HMAC on the decoded secret. A receiver that verified
  against the old signature rejects every delivery until it decodes too.
- `events/subscribe` sends a signed challenge to `delivery.url` and creates the
  subscription only if the receiver echoes it. A receiver that does not answer
  stops getting new subscriptions.
- `http://` callbacks are refused unless you opt in.

These are security changes as much as spec alignment. Before this release an
authenticated caller could name any URL and the server would POST events to it.
Verification POSTs are also rate-limited per destination host, 60 a minute by
default.

**The Go toolchain floor is now 1.26.6.** go1.26.5 has five reachable
standard-library vulnerabilities (`net/url`, `crypto/tls`, `net/http`,
`html/template`, `encoding/asn1`), all fixed in go1.26.6. Every module's `go`
directive moved, so building mcpkit needs go1.26.6 or later. (PR 1485)

**`cmd/mcpskills` builds again.** v0.6.0 removed the `ext/skills` index API but
not the command's use of it, so `cmd/mcpskills` at v0.6.0 does not compile. It
is fixed here. Install it from source for now: `go install …@v0.7.0` still fails
because of in-repo `replace` directives (issue 1488, see Known issues).

**This is also the first release whose tag-triggered workflows are expected to
run.** From v0.4.0 through v0.6.0, `make tag-push` sent all 20 tags in one
`git push`, and GitHub raises no push event for a push that large. So
`publish-images.yml` never ran and `vulncheck.yml` only ran on its weekly
schedule. The events images never reached GHCR. PRs 1411 and 1413 split the push
and added `make check-release-workflows V=<tag>`. Run it after tagging, since this
release is the first real exercise of its success path.

## Breaking

Two tagged modules break: `experimental/ext/events` and `ext/ui`. Nothing in
the root module breaks. One root-module behaviour change is listed under
Changed.

- **`experimental/ext/events`: webhook signatures key the HMAC on the decoded
  secret.** The spec defines the Standard Webhooks key as the base64-decoded
  bytes after the `whsec_` prefix. mcpkit keyed it on the literal `whsec_...`
  string. Its signer and every verifier it shipped made the same substitution, so
  round-trip tests passed while a receiver written by anyone else rejected every
  delivery.

  | | Was | Now |
  |---|---|---|
  | HMAC key for `whsec_MDEy...` | the 47-byte string | the 32 decoded bytes |

  The key is decoded only when the `whsec_` prefix is present. A secret that
  does not decode falls back to its literal bytes. The legacy `X-MCP-Signature`
  mode is unchanged, because the spec defines key derivation for the Standard
  Webhooks formula only.

  *Migration:* out-of-tree receivers must key the HMAC on the decoded secret.
  `eventsclient.Receiver`, the Python client and the whole-enchilada receiver are
  updated. Stored secrets need no change, since only the `whsec_` string is
  persisted. There was no dual-signing transition. (#1432)

- **`experimental/ext/events`: webhook endpoints are verified before any
  delivery.** `events/subscribe` POSTs a signed
  `{"type":"verification","challenge":"<nonce>"}` envelope to `delivery.url`
  and creates the subscription only if the endpoint echoes the nonce in a 2xx
  body. Otherwise it fails with `-32015` and `data.reason` set to
  `challenge_failed` or a connection category. The handshake is synchronous, so
  a slow endpoint adds up to the 5 s ack timeout to the subscribe call. A
  successful result is cached per `(principal, url)` and persisted on the
  subscription as `VerifiedAt`, so refreshes and restored no-expiry
  subscriptions do not re-verify.

  *Migration:* receivers must be listening before they subscribe and must answer
  the challenge. `eventsclient.Receiver` and the Python client answer
  automatically. Other receivers call `events.AnswerVerificationChallenge` after
  checking the signature. Operators can waive the handshake for known URLs with
  `WithWebhookDeliveryAllowlist`, `WithPreVerifier` or
  `WithPreVerifiedDeliveryURL`, or accept a receiver-published well-known
  document (see Added). `WithUnsafeSkipEndpointVerification()` restores the old
  behaviour. Subscriptions persisted before the upgrade have no `VerifiedAt`, so
  their first refresh runs a handshake. (#1444)

- **`experimental/ext/events`: `events/subscribe` and `events/unsubscribe`
  enforce what the spec says to refuse.** Three changes, each a caller relying on
  the old permissiveness will notice:

  | | Was | Now |
  |---|---|---|
  | `http://` callback | accepted | `-32602`, unless `WithUnsafeWebhookAllowPlaintextCallbacks()` |
  | subscribe for a mode the type does not advertise | accepted | `-32014 Unsupported` |
  | unsubscribe naming no subscription | success | `-32011 NotFound` |

  `WithWebhookAllowPrivateNetworks(true)` no longer implies plaintext. The two
  were fused, which meant a server that allowed loopback also stopped enforcing
  the scheme. In Go, `WebhookRegistry.Unregister` now returns a `bool` reporting
  whether anything was removed. Callers that ignore the result compile unchanged.

  The derived delivery set also changed. A source that leaves `Delivery` unset
  and is registered alongside a webhook registry now advertises `webhook` even
  when it cannot stream. Before, webhook was derived only for streamable sources,
  which was wrong from the start.

  *Migration:* use https callbacks, or pass the plaintext option for local
  development. Treat `-32011` from unsubscribe as "already gone". (#1434)

- **`experimental/ext/events`: `events/poll` honours the descriptor's `delivery`
  list.** Polling a type whose `delivery` omits `poll` returns `-32014
  Unsupported` with `data {feature: deliveryMode, value: poll}` where it used to
  return a result. A source that declares no `Delivery` gets a set derived at
  registration: `poll` always, `push` if it implements `Subscribe`, and
  `webhook` if a webhook registry exists. An explicit list is never widened or
  narrowed.

  *Migration:* if a source should answer polls, include `poll` in its
  `Delivery`, or leave the field unset. (#1416)

- **`ext/ui`: the bridge JS sends MCP Apps `2026-01-26` wire shapes.** A host
  written against the old bridge output needs updating. The JS call signatures
  are unchanged, so View code does not.

  | Call | Was | Now |
  |---|---|---|
  | `updateModelContext({content})` | `ui/update-model-context {context: {content}}` | `ui/update-model-context {content}` |
  | `downloadFile(url, filename)` | `ui/download-file {url, filename}` | `ui/download-file {contents: [{type: "resource_link", uri, name}]}` |
  | `requestTeardown()` | `ui/teardown` | `ui/notifications/request-teardown` |
  | `log(level, message)` | `ui/log {level, message, data}` | `notifications/message {level, logger, data}` |
  | host capabilities | read from `capabilities` | read from `hostCapabilities` |

  `hostCapabilities` was always `{}` against a spec host, so the last row only
  affects hosts that answered `ui/initialize` with `capabilities`. Messages from
  any window other than `window.parent` are now ignored, the same assumption
  upstream's `PostMessageTransport` makes.

  *Migration:* a host must answer `ui/initialize` with `hostCapabilities`, read
  the unwrapped `ui/update-model-context` params, and handle
  `notifications/message` and `ui/notifications/request-teardown` in place of
  `ui/log` and `ui/teardown`. `downloadFile` also accepts the spec `{contents}`
  object. The bridge still accepts the older `ui/resource-teardown`
  notification and the `{hostContext}` wrapper from hosts written against
  earlier drafts. (#1472)

Not breaking, though they look like it:

- **The Events capability is declared under
  `capabilities.extensions["io.modelcontextprotocol/events"]`.** v0.6.0
  declared no Events capability at all. PR 1416 added a top-level
  `capabilities.events`, and PR 1424 moved it into the SEP-2133 extensions map
  a week later, after the design sketch's author confirmed the sketch was wrong.
  No tagged release carried the top-level form, so the net change is additive.
- **Push frames carry the subscription id in `_meta`.** The top-level
  `requestId` is still sent, so existing clients are unaffected. (#1433)

## Added

### Events

- **Endpoint verification by receiver-published document**, opt-in via
  `WithWellKnownReceiverDocs()`. A callback counts as verified with no
  challenge POST when its https origin serves
  `/.well-known/mcp-webhook-receiver.json` listing a path prefix that covers
  it. Receivers publish one with `events.WellKnownReceiverHandler(prefixes...)`.
  A missing, malformed, oversized, redirected or plaintext document never fails
  a subscribe. It just verifies nothing, and the challenge decides. (#1449)
- **`YieldingSource.YieldGap`**, which sends a gap marker to subscribers
  without ending the stream. (#1427)
- **`CanonicalKey` and `DeriveSubscriptionID` are public.** They wrap functions
  the handler already used, and a test pins them to its computation. (#1430)
- **`WebhookRegistry.UnsafeAllowCallbackOrigins(origins...)`** lifts both
  callback guards, https and the SSRF dial guard, for the named origins while the
  process runs. It is all-or-nothing, so one malformed entry permits none. It
  exists for conformance harnesses that pick a loopback port at run time.
  (#1462)
- **`WebhookRegistry.PostGapByEventName`**, the sibling of
  `TerminateByEventName`, for sources that fan out to webhooks themselves.
  (#1469)
- **`EventsExtension` and `ExtensionID`** declare the capability through
  `srv.RegisterExtension`. `Register` does this for you. `core.EventsCap` is the
  settings object. (#1416, #1424)

### MCP Apps

- **`AppHost` answers the View's `ui/*` host requests.** `ui/open-link`,
  `ui/download-file`, `ui/message`, `ui/request-display-mode` and
  `ui/update-model-context` go to the `HostHandlers` passed with
  `ui.WithHostHandlers` instead of being forwarded to the MCP server, which
  cannot answer them. A nil handler returns `-32601`, bad params return `-32602`,
  and a handler can choose its own code with `ui.HostError`.
  `ui/request-display-mode` with no handler answers `inline`
  (`ui.DefaultDisplayMode`), since the spec requires an answer. Other View
  notifications reach `HostHandlers.Notification`. This changes what an
  existing `AppHost` does with those five methods, but they used to fail at the
  server as unknown methods, so no working setup depended on the old path. A
  fixture recorded from the real bridge JS is replayed through `AppHost` in
  tests. (#1477)
- **mcpkit's View extras work on upstream's `App`.**
  `ext/ui/assets/mcp-app-extras.js`, an ES module with types in
  `mcp-app-extras.d.ts`, exports the SEP-2356 file picker (`selectFile`,
  `selectFiles`) and `withTraceRelay(transport, provider)`, which stamps SEP-414
  trace context onto outbound requests and notifications of any MCP transport,
  upstream's `PostMessageTransport` included. The bridge imports the same
  modules. The file is vendored, not published to npm. (#1475, PR 1479)
- **`MCPApp.hostInfo`** exposes the host's `hostInfo` from the initialize
  result. (#1472)
- **New example, `examples/apps/any-frontend`.** One Go backend serves the same
  App through four View runtimes: the mcpkit bridge, upstream `App`, upstream
  React `useApp`, and upstream `App` with the extras. It also serves `/host`, a
  small reference host built on upstream's `AppBridge`. A Playwright suite drives
  every View in Chromium in CI, the repo's first browser test. (#1474, PR 1481)

## Changed

### Core

- **`core.ClientSupportsExtension` reads the SEP-2575 per-request envelope.**
  On the stateless wire there is no `initialize`, so the `_meta` envelope is the
  only place a client declares extensions, and the helper returned false for
  every stateless client. `ClientSupportsUI`, `ClientSupportsTasks` and the
  `BaseContext` methods route through it. An Apps server using the documented
  `ClientSupportsUI` check stopped serving its text-only fallback to stateless
  clients that asked for UI. Listed as a change rather than a break because
  the API is the same and the old answer was wrong. Nothing changes on the
  session wire. A handler that used a false answer to pick a stateless-safe path
  and then calls a session-only API such as `ctx.Elicit` would now reach it on
  the stateless wire. None exists in the tree. (#1458, PR 1470)

### Events

- **Verification POSTs are rate-limited per destination host**, 60 a minute
  with a burst of 60 by default. Over budget, `events/subscribe` answers
  `-32013` with `data.limit` `verifications_per_host` and sends no POST. Cache
  hits, allowlist matches and pre-verified URLs cost nothing. Tune with
  `WithVerificationRateLimit(max, window)`, and `(0, 0)` turns it off. (#1448)
- **A source's gap and termination reach its webhook subscribers.**
  `YieldGap` sends each webhook subscription of that type a
  `{"type":"gap","cursor":<Latest()>}` envelope. `YieldTerminated` sends a
  `terminated` envelope with the source's error and removes the subscription.
  `PostGap` with an empty cursor now sends nothing and logs, since a type with
  no replay has no position to have advanced past. (#1469)
- **Push frames carry the subscription id** under
  `io.modelcontextprotocol/subscriptionId` in `_meta`, on all five
  `notifications/events/*` frame types. The id is copied per frame, so two
  subscribers never see each other's id. `requestId` stays. (#1433)
- **The TTL expiry sweep also runs from `Deliver`**, throttled to once a minute
  or once per quarter-window. TTL-expired targets are pruned there too, so
  their `onRemove` hooks can fire from the delivery path rather than waiting for
  the next `Register`. (#1447)

### Examples

- **The events stack is one compose file.** `docker-compose.yaml` is gone.
  `events-stack.yaml` is the only stack definition, and `make up` layers
  `compose.dev.yaml` over it. `make up` is auth-on and waits on healthchecks.
  The first `make up` creates fresh named volumes, so subscriptions in the old
  `docker/backends` volume do not carry over. Local tooling that runs a bare
  `docker compose` in that directory needs `-f`. Three follow-ups fixed the exec
  bit on `smoke-stack.sh`, recipes still using the old layout, and
  `just clean-backends`, which wiped the events volumes instead of backends.
  (#1384, PRs 1392, 1394, 1395, 1396)
- **`examples/agents/deep-agent-supervisor` is removed.** Its host left the
  repo with the agent SDK. `experimental/ext/agents` stays, with its own tests.
  (#1404, #1409)
- **kitchen-sink gains `--conformance-events`**, which registers the
  diagnostic controls the Events conformance suite drives: yield gap,
  terminate, tenant identity, restart over the same store, callback-origin
  permit, quota report, and per-subscription webhook gap and terminate. They
  call public library API and gate the trigger, never the behaviour. (#1427,
  #1429, #1430, #1446, #1447, #1462, #1464, #1467)
- `examples/host` pins demokit at v0.0.32 instead of a `replace` pointing
  outside the repository, so `go.sum` covers it. (commit `3853a192`)

## Fixed

### Events

- **`events/poll` always returns an `events` array**, never null or absent.
  (#1416)
- **`events/list` is sorted by name.** It ranged a map, so the order flapped.
  This is the same bug as PR 1408 on the apps bridge, and it became constraint
  C10. (#1416)
- **Failure-based GC drops suspended no-expiry webhook subscriptions.** A
  suspended target received no deliveries, so its GC window was never checked
  again and it stayed in the store indefinitely. (#1447)
- **Push no longer sends `truncated: true` when the source has no position**,
  meaning a cursorless source or one that has yielded nothing. The spec says
  `truncated` SHOULD be false for a type without replay. (#1468, PR 1471)
- **`stores/gorm` persists `VerifiedAt`, `Subject` and `SessionID`.** Without
  the last two, a subscription restored after a restart could not be matched by
  backchannel logout, so revoking the session that created it did not stop its
  deliveries. New columns default to `''` and `AutoMigrate` adds them. Existing
  rows keep empty values until re-created. (#1444, #1445)
- The discord walkthrough subscribes with `arguments`, not `params`, and the
  skills security harness asserts the `ResolveRelative` defense for a `file://`
  reference. (#1445)

### MCP Apps

- **The bridge answers `ui/resource-teardown` as a request and answers
  `ping`.** It used to return Method not found for a spec teardown request.
  Host-context updates merge instead of replacing, `toolcancelled` carries
  `reason`, `ui/notifications/initialized` goes out before anything a
  `connected` listener sends, and `appCapabilities.tools` is declared when tools
  are registered before the handshake. (#1472)
- **`InProcessAppBridge` returns `tools/list` in a stable order.** It ranged a
  map, which made `examples/host/01-apphost`'s generated README differ on every
  run. (#1408)

### Skills

- **`cmd/mcpskills` compiles against the current `ext/skills`.** At v0.6.0 it
  called `ListSkills` and `ErrNestedSkill`, both removed by the SEP-2640
  2026-08-21 revision that release shipped, so the command did not build.
  `inspect` now lists skills with `skills/list` and checks every pinned file of
  each skill rather than one URL. Its JSON output drops `indexSchema` and `type`
  and adds `files` and `dynamic`. `verify` accepts nested `SKILL.md` files, as
  the revision allows. `examples/mcpskills-walkthrough` reads the new
  `inspect --json` shape. (PR 1487)

## Build and CI

- **Tagged sub-modules pin sibling modules at v0.7.0.** Earlier releases left
  sibling pins one release behind, which is only safe while no sub-module uses
  newer sibling API. This release breaks that assumption:
  `experimental/ext/events/stores/gorm` uses the `VerifiedAt` field from #1444,
  which `events@v0.6.0` lacks. So `stores/gorm`, `stores/memory`,
  `stores/redis`, `clients/go`, the agents client, `cmd/mcpskills` and
  `cmd/testclient` now require their siblings at v0.7.0, and
  `go get …/stores/gorm@v0.7.0` pulls a compatible `events`.
- **Go toolchain floor raised to 1.26.6** across all 79 modules, clearing
  GO-2026-6218, GO-2026-6090, GO-2026-6089, GO-2026-6091 and GO-2026-5972 (and
  GO-2026-5026 via `net/http`). `make audit`'s `govulncheck` stage was red on
  go1.26.5. (PR 1485)
- **Release workflows fire on tags.** `make tag-push` pushes the root tag on
  its own and then the sub-module tags (#1411).
  `make check-release-workflows V=<tag>` asks the Actions API whether each
  tag-triggered workflow ran against a tag, and `RELEASING.md` now includes it
  as a step. It derives its list from `on.push.tags`, so a new tag-triggered
  workflow is covered without edits. `DEPENDENCY_POLICY.md` no longer claims
  the audit ran before every tagged release. (#1413)
- **Constraint C8: recipes dispatch, they do not hold shell scripts.** A recipe
  with control flow or four or more statements belongs in `scripts/`.
  `make check-recipe-complexity` gates it in `test.yml`. The sweep extracted
  every baselined recipe across the tree, and the baseline went from 66 to 0.
  It found and fixed drift along the way, including a `check-conformance-stale`
  that diffed different files in make and just, and a `cover-all` path that only
  worked for two-level modules. (#1397, #1399, #1400, #1401, #1402, #1404)
- **The `ext/ui` bridge tests run in CI** and check every outbound message
  against upstream's ext-apps schemas. This also fixed a `pnpm-workspace.yaml`
  placeholder that broke `pnpm install --frozen-lockfile` and a `tsconfig.json`
  that TypeScript 7 rejected. `check-bridge.sh` fails on a stale
  `mcp-app-extras.js` as well as a stale bridge. (#1472, PR 1479)
- **The `client` `list_changed` tests wait for the GET SSE stream** before
  registering a tool, so the broadcast can no longer race ahead of the listener
  and flake the coverage run. Contributed by hy3560. (#1482, PR 1484)
- `TestWaitForTaskTimeout` compares errors with `errors.Is`. It raced between a
  bare and a wrapped deadline error. (#1406)

## Conformance

- **`testconf-events` drives all five scenarios.** Discovery 12/12, poll
  30/30, push 20/20, webhook 25/26, webhook-delivery 23/23. The suite surfaced
  thirteen divergences in mcpkit's own implementation, and all are closed. The
  one red row, `subscribe-auth-required`, is untestable rather than a defect,
  because the harness holds one credential and kitchen-sink uses an anonymous
  principal by design. Stage 8i stays `INFO` while the design sketch has no SEP
  number. (#1426, #1428, #1446, #1447, #1462, #1464, #1467, #1471)
- Server and client tier-check are unchanged at 31/31 and 21/21.

## Docs

- `docs/APPS_DESIGN.md` records **frontend independence** as a design decision.
  mcpkit's Apps support is the Go backend, any View runtime that speaks the
  `2026-01-26` wire works with it, upstream's `App` is the recommended runtime
  for single-page apps, and the bridge stays optional. (PR 1476)

  subscribers receive. `DEPLOYMENT.md` covers endpoint verification. (#1444,

## Known issues

- **`go install github.com/panyam/mcpkit/cmd/mcpskills@v0.7.0` fails.** Tagged
  modules carry in-repo `replace` directives for local development, and
  `go install pkg@version` refuses a module that has them. Library consumers are
  unaffected, since `go get` ignores a dependency's replaces. Build the command
  from a clone (`make build-mcpskills`) until issue 1488 lands. The same applies
  to `cmd/testclient`.
- **CI does not build tagged sub-modules against main** (issue 1486). That gap
  is how `cmd/mcpskills` shipped broken in v0.6.0.

# mcpkit v0.4.0

**Status: released 2026-08-03.** 0.4.0 is the stable cut of a bundle of
backward-incompatible API changes queued behind a version boundary. It was
tagged once the whole bundle was complete and `just audit` / `just testall` /
`just testconf` were green on go1.26.5. The agent modules (`agent`,
`agent/host`, `agent/store/*`, `cmd/agentchat`) are excluded from this release's
tag set and continue on their own independent cadence.

## Framing

0.4.0 gathers the API breaks we deliberately queued behind a version boundary
while mcpkit still has no external clients to migrate. It is an **API**-breaking
release, not a **protocol**-breaking one: no protocol capability is removed.

The SEP-2577 Roots / Sampling / Logging surfaces are **kept** in 0.4.0 with their
existing `// Deprecated:` annotations and full runtime behavior. Their removal is
deferred to a later release, no earlier than the spec itself drops them (~2027),
per [`docs/SEP_2577_DEPRECATIONS.md`](../SEP_2577_DEPRECATIONS.md). Two reasons
beyond the date gate:

1. mcpkit's own deprecation window is 12 months from the 2026-05-31 annotation
   pass (to ~2027-05-21); removing at a July-2026 tag would break that promise.
2. Those features are deprecated-but-still-in-spec on the targeted spec version,
   so conformance tests still count them. Deleting them would drop mcpkit below
   100% conformance and out of Tier-1 eligibility.

## Scope (confirmed)

### Breaking (this cut)
- [x] **#496** conformant-by-default — SEP-2549 list + `resources/read`
      cache-control hints emit by default (list `ttlMs:0`/`public`, read
      `ttlMs:0`/`private`); `server.WithoutListCacheControl()` /
      `server.WithoutReadResourceCacheControl()` opt out.
- [x] **#774** lift `QuotaStore` to root `stores/`, rename `EventName` → `Key`
      (events re-exports via aliases; gorm column `event_name` → `quota_key`,
      fresh-deploys-only).

### Added / Fixed (this cut)
- [x] **Go toolchain floor → 1.26.5** — clears GO-2026-5856 (crypto/tls ECH
      privacy leak) across root + all sub-modules; govulncheck green.
- [x] **`Client.transport` data race fixed** — `doConnect` publish vs `Close`
      read (reachable via `client.Group` async connect) now synchronized on the
      existing `Client` mutex, lock scoped so close-during-connect never hangs.
- [x] **#420** panic recovery — `Dispatch`-level recover (all sync
      tool/prompt/resource/completion handlers → `-32603`, no host crash) +
      `safeGo` wrapping every library-owned background goroutine across
      server / client / ext-ui / events / events-go-client
- [x] **#485** v2 task-store multi-tenant isolation — `server.WithTaskBucketKeyer`
      (ctx → bucket; default = session ID; no `ext/auth` dep), applied on both wires
- [x] **#829** `ClientModeStateless` connects to discover-less draft servers
- [x] **#838** `Mcp-Name` validation for `prompts/get` (SEP-2243)
- [x] **#422** validate `MCP-Protocol-Version` header vs body on `initialize`
- [x] **#421** reject duplicate `initialize` after session established (opt back in with `WithAllowReinitialize()`)
- [x] **Gap 1** spec-compliant version negotiation — unsupported requested
      `protocolVersion` negotiates the server's preferred version and replies
      with it instead of erroring (MCP 2025-03-26 §Version Negotiation)
- [x] **Gap 3** version feature-set resolver (`server/protocol_features.go`) —
      single table for version-gated behavior across both wires

### Deprecated (unchanged — removal deferred)
- SEP-2577 Roots / Sampling / Logging kept as-is with `// Deprecated:` blocks.
  Removal tracked separately for a ~2027 release.

### Already-landed breaks carried since 0.3.0 (documented, no work)
- Sealed-interface `ToolResponse` / `PromptResponse` (#486 / PR 487)
- events `params` → `arguments` (PR 778)
- events error-code generalization (#491)
- `UnsupportedProtocolVersion` → -32022; stateless `resources/read` cache defaults

## Deferred (recorded, not gating this release)
- **#493** collapse `server/stateless` into `server/` — moved off the 0.4.0
  breaking bundle onto the legacy-wire removal track. The import-path break
  (`stateless.Mode` → `server.Mode`, etc.) is the natural last step of removing
  the stateful wire (~2027), where it rides an already-breaking cut instead of
  spending a fresh break now. The internal single-`Dispatcher` merge (the
  maintainability half) can be done non-breaking with a `server/stateless`
  re-export shim any time the 2x-diff tax bites. See issue 493.
- **#317** SEP-2643 error code — spec integer still TBD; land when assigned.
- **#426** v1 task-surface retirement — keep the frozen v1 surface for now; cut
  it alongside the SEP-2577 removal.
- **#835** `ctx.Elicit` / `ctx.Sample` → MRTR — deferred; sampling is kept only
  for back-compat/conformance, not worth new investment now.
- **#531** server-card SEP-2127; **#780 / #782 / #749** ext/skills WG-dependent;
  **#490 / #407** events endpoint verification + demos umbrella.

## Tier 1 follow-up (separate track, not gating 0.4.0)
Recorded so it isn't lost. Qualifying for MCP SDK **Tier 1** additionally needs:
100% conformance on the targeted spec version, a production-ready **1.0.0**
stable release (0.x doesn't satisfy the "stable release" bar), the standardized
issue labels (`bug`/`enhancement`/`question` + status + `P0..P3`), a published
dependency-update policy, and a published roadmap — then a WG advancement request.
See #431.

# v0.8.5

A patch release for agni. The room bridge's page client now joins through
massrelay's own `CollabClient`, on massrelay 0.2.4, and the dependencies
massrelay moved (oneauth, servicekit) move across the whole tree with it. The
Keycloak interop suite runs in CI for the first time, and its first run found
two tests that had only ever passed on macOS.

## Changed

- **massrelay v0.2.4** in `experimental/ext/rooms/massrelay`, and
  `@panyam/massrelay` ^0.2.4 in the page client. (PRs 1596, 1598)
- **The page client joins through `CollabClient`.** It uses its `token`
  option, refuses room-wide messages by `toClientId`, and stays in the room when
  a reply goes to an agent that has already left. Its public `joinToolRoom` API
  is unchanged. (PR 1598, massrelay issues 31 and 33)
- **oneauth v0.3.0** (was v0.2.2) and **servicekit v0.1.9** (was v0.1.7) in
  every module, the root included. No source changes were needed. `make test`,
  `test-auth`, `test-e2e` and the Keycloak suite pass on both. (PRs 1596, 1598)

## Fixed

- **The post-publish smoke test sends SEP-2243 routing headers.** Since #1567
  it had failed on every tag, v0.8.3 and v0.8.4 included, after the images
  themselves published fine. (PR 1595)
- **`TestKeycloak_StepUp_StatelessWire` sends the routing headers too**, and
  passes again. It had been red since #1567, unnoticed because the suite ran
  nowhere. (PR 1596)
- **The backchannel-logout tests pass on Linux.** The Keycloak container maps
  `host.docker.internal`, and the test's callback server listens where the
  container can reach it. (PR 1599)

## CI

- **The Keycloak interop suite runs** on PRs touching `ext/auth`, `client`,
  `server`, `core` or the suite, on pushes to `main`, and nightly. It takes
  about 50 s, in parallel with `test`. An unreachable Keycloak now fails the
  run (`KEYCLOAK_REQUIRED=1`) instead of passing it as 19 skips, and
  `make testkcl-auto` refuses a port someone else's server holds. (PR 1599,
  issue 1597)

## Upgrading downstream

- **agni**:
  `go get github.com/panyam/mcpkit/experimental/ext/rooms@v0.8.5 github.com/panyam/mcpkit/experimental/ext/rooms/massrelay@v0.8.5`.
  This brings in massrelay v0.2.4, oneauth v0.3.0 and servicekit v0.1.9.
  The page client still isn't on npm. Depend on `experimental/ext/rooms/ts`
  from the v0.8.5 tag, with `@panyam/massrelay` ^0.2.4.
- **chakra and others on oneauth or servicekit**: expect go.mod to move to
  oneauth v0.3.0 and servicekit v0.1.9.

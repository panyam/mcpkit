# v0.8.4

The release that makes the room bridge usable end to end, which is what agni's
design viewer needs. A web page can offer tools in a massrelay room, and an
agent calls them through the bridge over MCP. This release adds the massrelay
transport (Go) and the page client (TypeScript) on top of the bridge itself,
which v0.8.3 carried. v0.8.3 was tagged without an announcement, so its changes
are summarised here as well, and [its note](v0.8.3.md) has the detail.

The client also picks up cancellation and progress for tool calls, and the
server gets a session-close hook that extensions can use.

## Added

- **The room bridge's massrelay transport**,
  `experimental/ext/rooms/massrelay`, its own module. (PR 1591, issue 1581)
  - `Embedded(svc, principal)` joins a relay running in the same process.
  - `Dial(baseURL, token)` joins a remote relay over its WebSocket protocol.
  - A peer's identity is the validated `sub` from its relay token, and every
    message is addressed to one peer.
- **The TypeScript page client**, `experimental/ext/rooms/ts` (package
  `@panyam/mcpkit-rooms`, private for now). (PRs 1592 and 1594, issue 1581)

  ```ts
  const room = await joinToolRoom({ relay, room: "design:demo/board.kicad_sch", token });
  room.registerTool({ name: "show_sheet", description: "...", inputSchema, async execute(args, { signal }) { ... } });
  ```

  - Tools use WebMCP's `registerTool` shape, so a page written for WebMCP works
    unchanged.
  - `registerOnApp` puts the same tool on an ext/ui app frame.
  - `modelContext: true` also registers the tool with the browser's own WebMCP
    context when there is one.
- **`ToolCallWith(ctx, name, args, client.WithProgress(fn))`** delivers that
  call's `notifications/progress` to `fn`. (PR 1587, issue 1585)
- **`Server.OnSessionClose(fn)`** runs once per session, whether the session
  ends by `DELETE`, by idle expiry or by its transport closing. (PR 1587)
- **`core.InsufficientScope(scopes...)` and `ScopeChallenge.AuthError(prmURL)`**
  build the 403 `insufficient_scope` response, so an extension can refuse a
  call without depending on `ext/auth`. (PR 1587)
- **Events:**
  - `Event.SubscriptionID` carries the `X-MCP-Subscription-Id` header.
  - `Subscription.StopAndUnsubscribe(ctx)` stops the subscription and
    unsubscribes upstream.
  - A watch on the events bridge can take a `tools` list that narrows what its
    runs may use. (PR 1588)

## Changed

- **Cancelling a call's context sends `notifications/cancelled`.** The stateless
  wire is the exception, since it has no such notification. Over stdio,
  in-process and the legacy SSE transport, a cancelled call now returns at once
  instead of waiting for the tool to finish. (PR 1587)
- **The room bridge ends a session's pairings when the server closes the
  session.** A host no longer has to call `Bridge.EndSession`. (PR 1590)
- **Dependencies converged on massrelay v0.2.1's versions** across every module:
  x/net, x/crypto, x/sys, x/text, otel, genproto, and servicekit v0.1.7.
  (PR 1591)
- **Constraint C10** now reads "stable order, never map iteration order".
  Registration order is acceptable, and list responses are unchanged. (PR 1587)

## From v0.8.3

- The room bridge itself, `experimental/ext/rooms` (PR 1584).
- The events bridge, `experimental/ext/events/clients/go/bridge` (PR 1583).
- The Go events client drops duplicate deliveries by default, and `Receiver`
  refuses webhooks timestamped more than five minutes from its clock (PR 1582).
- The stateless wire requires SEP-2243 routing headers (issue 1567).

## Upgrading downstream

- **agni**:
  - Go side: `go get github.com/panyam/mcpkit/experimental/ext/rooms@v0.8.4 github.com/panyam/mcpkit/experimental/ext/rooms/massrelay@v0.8.4`.
  - Browser side: the page client isn't on npm yet. Depend on
    `experimental/ext/rooms/ts` from the v0.8.4 tag until it's published as
    `@panyam/mcpkit-rooms`. It needs `@panyam/massrelay` 0.2.1 or later.
- **chakra**: `ToolCallWith` and `OnSessionClose` are new API, and nothing
  existing changed shape. The v0.8.3 receiver changes apply if you consume
  webhooks.
- **Known gaps**:
  - `client.Close` still sends no `DELETE` for a Streamable HTTP session, so the
    server notices only at idle expiry (issue 1589).
  - massrelay's `CollabClient` can't join an authenticated room yet
    (massrelay issue 31), which is why the page client uses servicekit's
    WebSocket client directly.

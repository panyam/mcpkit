# v0.8.3

A patch release that's mostly about events, cut so agni can depend on the new
`experimental/ext/rooms` module. It adds two experimental pieces, a room bridge
that lets an agent call tools a web page offers, and an events bridge that lets
an agent watch for events and have them acted on without the user present. The
Go events client now dedups and refuses replayed webhooks by default.

Both bridges are experimental and pre-SEP, so they're outside the stability
promise, as `experimental/` is generally.

## Added

- **`experimental/ext/rooms`, the room bridge.** (PR 1584, issue 1581, slice 1)
  A page joins a room for the resource it shows and offers tools there. The
  bridge is an MCP server to agents and an MCP client to each page.
  - Agents get `attach`, `detach` and `list_pages`, plus each page's tools with
    an optional `page` argument.
  - Every call goes to exactly one page: the named one, else the paired one,
    else the only one.
  - Pairing is a same-user switch on the page, or a short code when the users
    differ.
  - Scopes `rooms:attach`, `pages:read` and `pages:act` are checked, with an
    `insufficient_scope` challenge when one is missing.
  - The transport is an interface (`RoomTransport`) with an in-memory relay
    (`memroom`). The massrelay adapter and the TypeScript page client come in
    later slices.
- **The events bridge**, `experimental/ext/events/clients/go/bridge` with the
  daemon `cmd/events-bridge`. (PR 1583, issue 1579)
  - Tools `watch_list`, `watch`, `unwatch` and `watches` work across every event
    type and server.
  - A watch stores the user's instruction. Each occurrence starts a headless
    `claude -p` with that instruction, the payload fenced as untrusted data, and
    an explicit tool list. Outward-facing tools need an `Approver`'s yes.
  - A watch can carry `session {id, dir}`. Each occurrence then resumes a fork of
    the session that set it up (`--resume --fork-session`), and falls back to a
    fresh run when that session is gone.
  - Watches, secrets and cursors persist across restarts.
- **`eventsclient.Deduper`** and **`eventsclient.EventSink`**. (PR 1582, issue 1558)

## Changed

- **The Go events client drops duplicate deliveries by default.** `Poll`,
  `Stream`, `StreamChan` and `Receiver` skip a second sighting of an `eventId`.
  Share one `Deduper` across modes to drop the overlap between them. Opt out
  with `AllowDuplicates` or `WithoutDedup()`. (PR 1582)
- **`Receiver` refuses webhooks timestamped more than five minutes from its
  clock**, so a captured POST can't be replayed later. `WithTimestampTolerance`
  changes the window, and `0` turns it off. A host with a badly skewed clock will
  see 401s. (PR 1582)
- **The stateless wire requires SEP-2243 routing headers** (`Mcp-Method`, and
  `Mcp-Name` on the methods that carry one, `events/*` included), or it answers
  400 with `-32020`. (issue 1567)
- **`whsec_` secrets are generated as standard padded base64.** (issue 1574)

## Fixed

- **`Receiver.Close` racing an in-flight delivery** no longer panics with "send
  on closed channel". (PR 1583)

## Upgrading downstream

- **agni**: `go get github.com/panyam/mcpkit/experimental/ext/rooms@v0.8.3`.
  The Go side is all here. The browser side (`joinToolRoom`) is the next slice
  of issue 1581.
- **chakra**: if you consume webhook deliveries through
  `eventsclient.Receiver`, retries no longer reach you twice, and stale
  timestamps are refused.
- Anyone calling a stateless mcpkit server over raw HTTP has to send the
  routing headers (`server/streamable_stateless_test.go`'s
  `stampRoutingHeaders` shows how).

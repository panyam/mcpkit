# v0.8.19

A patch release for chakra's side of the room bridge. A host can now open its room event
subscriptions as soon as it connects, before it calls `attach`, and start hearing events once it
attaches. The Lanternfall example also shows the game master's context live, including
compaction, in a layout that keeps every panel on screen.

## Upgrade notes

- **A room event subscription or poll before `attach` now succeeds quietly** where it returned
  `-32024` Forbidden. It hears nothing until the session attaches, and then only events from after
  the attach. A host that ordered a setup call before its subscriptions (chakra#312) can drop that
  ordering for room events. A call with no MCP session is still refused. (PR 1688)

## Added

- **`rooms.Bridge.AttachedSince(session, resource)`** reports when a session attached to a room,
  kept through a repeated `attach` and dropped on `detach`. (PR 1688)

## Changed

- **roomsevents accepts a subscription from any MCP session**, attached or not, and delivers an
  event only while the session is attached, only if the event happened after it attached, and only
  from pages that agreed to it. `events/poll` from a cursor taken before the attach replays nothing
  from before it. `detach` pauses a stream, and attaching again resumes it. (PR 1688)

## Examples

- **The Lanternfall game master keeps one conversation for the game.** Every event, question, tool
  call and result is a message in it. Past a token budget it asks the model to summarize the
  conversation and carries on from the summary, keeping the latest `session`-retention event. A
  `last-wins` event now replaces only an older one the model has not seen.
- **A "Game master's context" panel** shows exactly what the model is sent, a token estimate
  against the budget, and each compaction, from a stream the game master serves on localhost
  (`--context-port`, 8091). It shows only a game master playing that tab's game and player.
- **A border layout** keeps the map, story, activity and context on screen at once.

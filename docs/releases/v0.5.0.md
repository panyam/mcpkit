# mcpkit v0.5.0

0.5.0 lands the agent web surface, threads `context.Context` through the whole
client I/O surface, and closes the last documentation gap in mcpkit's Tier 1
posture. It is API-breaking on the client and on two module paths, and removes
no protocol capability.

Scale since 0.4.0: 133 commits, 49 pull requests, 536 files, +24.6k/-3.9k.

## Framing

Two thirds of this release is the agent layer. The web UI epic (issue 1193)
turned `agent/host` from a thing only a terminal could drive into a host with
two live surfaces sharing one session, which is what the host was designed for
and what had never been proven.

The rest divides into three: a breaking but mechanical client change that makes
every call cancellable, a documentation push that took the SEP-1730 audit from
42/48 to 48/48, and a security and supply-chain pass that found four reachable
advisories nothing was previously scanning for.

## Breaking

### Every client method that performs I/O takes a `context.Context`

Sixteen methods gained a leading `ctx`. `Connect`, `Call`, `CallContext`,
`ToolCall`, `ToolCallFull`, `ReadResource`, `ReadResourceFull`, `SetLogLevel`,
`NotifyRootsChanged`, and the `ListXPage` family. Accessors that touch no
network (`SessionID`, `URL`, `ServerSupportsUI`) are unchanged.

```go
// before
c.Connect()
out, err := c.ToolCall("greet", args)

// after
ctx := context.Background()
c.Connect(ctx)                       // bounds the handshake, not the session
out, err := c.ToolCall(ctx, "greet", args)
```

The client was previously split down the middle: the paginated list methods took
a `ctx` while `ToolCall`, `ReadResource`, `Call`, and `Connect` did not. That
meant no cancellation or timeout on the calls people make most, and a latent
panic where callers reasonably passed a context to methods that ignored it.

Migration recipe with the full method table: `docs/CLIENT_CONTEXT_MIGRATION.md`.

### `Server.Register` is strict

`Register` now rejects a malformed registration instead of accepting it and
failing at dispatch time.

### `agent/web` moved to `agent/surfaces/web`

The surfaces were grouped under one parent so a surface-agnostic host has a
single place to put them. `cmd/agentchat` became `agent/surfaces/chat`. Import
paths change accordingly; there is no compatibility shim, because the agent
modules have never carried a release tag.

### Elicitation responses are validated

An accepted `elicitation/create` response is now checked against the server's
`requestedSchema` before being sent. A handler returning a string where the
server asked for an `integer`, a value outside a declared `enum`, or omitting a
`required` property gets `-32602` with a structured error list instead of
silently forwarding content the server said it could not accept.

Opt out with `client.WithElicitationValidation(false)`. This mirrors
`server.WithSchemaValidation(false)`; both default to on.

## Added

### Agent web surface (issue 1193)

A browser surface over the same `agent/host` the terminal drives, viewable at
the same time on the same session.

- Per-session event log on `gocurrent.Queue`, replacing the `Observer` fan-out,
  with replay from offset 0 so a tab joining a live session sees history
  (PR 1201, bounded in PR 1211).
- Pending-ask barrier so an elicitation reaches every surface, first answer
  wins, and the others retract with a receipt naming the winner (PR 1205, 1210).
- `agent/surfaces/web` submodule: Connect bridge with a server-streaming
  `Watch`, plus `Submit`, `Dispatch`, and `RespondToAsk` (PR 1206).
- DockView + Solid frontend with five observability panels: sub-agent tree,
  activity timeline, memory inspector, tool-call and offload inspector, and
  budget gauges (PR 1208, 1209).
- Multi-session routing by `session_id` and RunStore-backed persistence
  (PR 1214, 1226).

### Server-declared agent discovery (epic 1142)

`experimental/ext/agents` implements the Agents WG pre-SEP wire primitive:
`agents/list` returns a roster without tool schemas, `agents/get` resolves one
agent's instructions and scoped tools. Only discovery is new wire surface;
invocation rides the existing `tools/call`. Includes a Go client SDK, a bridge
turning an `agents/get` result into an `AgentSource` (PR 1186), SEP-414
discovery spans (PR 1190), and a deep-agent supervisor demo (PR 1191).

### Server readiness signal

`srv.Ready()` closes once the listener is bound, and `srv.Addr()` reports the
bound address, so starting a server in a goroutine no longer needs a
`time.Sleep`. `RunWithListener(ln)` lets the caller own the bind entirely.

### Documentation: SEP-1730 audit 42/48 to 48/48

Four primitive guides where there were none: `docs/COMPLETIONS.md`,
`docs/PROMPTS.md`, `docs/ELICITATION.md`, plus a Ping section in
`ARCHITECTURE.md`. Completions was the only core capability slot with zero
user-facing documentation, and prompts was the only core primitive with no
dedicated prose anywhere.

Backed by **25 Go `Example` functions**, where the repo previously had none.
They run under `go test`, so the guides cannot drift from the code. Writing them
surfaced four errors that would otherwise have shipped, including a wrong error
code and a stale doc comment (PR 1229, 1231, 1232, 1233).

### Signals and composition

The `preempt` signal kind with a kind-aware barrier break, parent-granted rather
than child-authoritative (PR 1178), and the opt-in interruptible turn (PR 1170).

## Fixed

### Four reachable advisories nothing was scanning for

`govulncheck ./...` is module-scoped and does not descend into nested modules,
so running it from the repo root scanned the root and nothing else. All 24
published sub-modules were unscanned, including `ext/auth`.

Fixing the scan (PR 1216) immediately surfaced four advisories reachable from
mcpkit's own code, since fixed (PR 1222):

| Advisory | Dependency | From | To |
|---|---|---|---|
| GO-2025-3540 | `redis/go-redis/v9` | v9.7.0 | v9.7.3 |
| GO-2026-5970 | `golang.org/x/text` | v0.33.0, v0.37.0 | v0.39.0 |
| GO-2026-6061 | `google.golang.org/grpc` | v1.81.1 | v1.82.1 |
| GO-2026-5004 | `jackc/pgx/v5` | v5.6.0 | v5.10.0 |

`stores/redis` is tagged and published, so 0.4.0 shipped with a reachable
go-redis advisory.

Also fixed: a vulnerable pillow resolution kept alive purely by a
`requires-python = ">=3.9"` floor nothing needed (PR 1236), and a `pre-push`
hook that had been blocking every push for anyone who installed it (PR 1224).

## Changed

### Dependency and supply-chain machinery

- A weekly `vulncheck` workflow and a monthly repo-wide dependency sweep, both
  time-triggered because the advisory database moves independently of the code
  (PR 1224, 1227).
- `make check-dep-consistency` fails CI when a third-party dependency is pinned
  at two or more versions across published modules, because MVS resolves to the
  maximum and a split pin means some modules silently build against a version
  their `go.mod` does not name.
- `make check-dependabot-dirs` fails CI when a configured Dependabot directory
  no longer exists. Dependabot ignores a missing directory without warning, and
  one npm tree had gone unmonitored that way (PR 1236).
- Dependabot rescoped: Go updates move as one lock-step sweep rather than
  per-directory PRs, which could not satisfy the lock-step rule the policy
  requires.

### `make` is the only task runner CI uses

CI installed a third-party action to run six recipes that `make` already had.
`make` is preinstalled everywhere, so the dependency bought nothing (PR 1235).
Justfiles remain as an experiment; `make` is authoritative when they disagree.

### Repository history rewritten

141 MB of committed build artifacts were purged with `git-filter-repo`, taking
the repository from 466 MB to 23 MB. Commit SHAs changed; no published module
content did. Every tag's tree SHA was compared before and after to prove it, so
`sum.golang.org` checksums for released versions remain valid.

A `pre-commit` hook and a CI gate now reject committed executables by magic
bytes, since the cleanup is only worth doing once.

### Skills hardening (SEP-2640)

Host-side origin tagging and per-origin name resolution, so a skill body carries
its origin label before entering context and a bare skill name served by more
than one origin returns a disambiguation prompt rather than silently
first-matching (PR 1185). Plus a security and conformance harness (PR 1187).

## Deferred

- **v1.0.0.** Every Tier 1 gate is now green except the stable-release check,
  which requires a major version of 1 or higher. That is a commitment decision,
  not remaining work.
- **SEP-2631 file objects.** The working group closed SEP-2356 on 2026-06-26 in
  favour of SEP-2631, which is still draft. mcpkit's file-input surface keeps
  working and is still exercised; the row is relabelled rather than presented as
  conformance to a live proposal. Migration tracked in issue 827.
- **Walkthrough deep-dives.** 15 of the `tutorials/walkthrough/` pages remain
  staged outlines. They are not part of any tier requirement.

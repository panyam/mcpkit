# v0.8.8

This is the first release whose commands install with `go install …@v0.8.8` (issue 1488). Up to
v0.8.7, every command in a tagged module refused to install, because each tagged `go.mod` carried
the in-repo `replace` lines we use for local development, and Go won't `go install pkg@version` a
module that has any. The tags now point at a commit with those lines stripped, and the next commit
on `main` puts them back.

The stateless wire runs the middleware chain on every method now (issue 1355). The room bridge
picks up presence, fan-out to many tabs, and a dynamic catalog for stateless callers, all of it
opt-in or additive.

## Fixed

- **Commands install from the proxy.** These all install now:
  - `cmd/mcpskills` and `cmd/testclient`
  - `experimental/ext/events/clients/go/cmd/events-bridge` and `…/cmd/conformance-client`
  - `experimental/integrations/roomsevents/cmd/rooms-channel`
  - `ext/auth/cmd/mcp-auth-proxy`
  - `examples/mcpskills-walkthrough`

  ```
  go install github.com/panyam/mcpkit/cmd/mcpskills@v0.8.8
  ```

  `make check-install V=` checks them all after a tag, and CI rehearses a release at a fake
  version on every PR. (PR 1624)
- **The stateless wire runs middleware on list methods.** `tools/list`, `resources/list`,
  `resources/templates/list`, `prompts/list` and `completion/complete` skipped the middleware chain
  on the SEP-2575 wire, so a middleware that filtered a list held on the session wire only. All five
  go through `InvokeWithMiddleware` now, with the same `ttlMs` / `cacheScope` hints as before, and
  `check-stateless-middleware` allows no exceptions. (PR 1619)

## Added (room bridge)

- **Presence.** Each page gets `notifications/rooms/presence`, listing the principals that called it
  or attached to its room, with a last-seen time and never a session id. Pages merge reports from
  every bridge in the room and drop an entry an hour after it was last seen.
  - Go: `Page.OnPresence`, `Page.Presence()` and `WithPresenceTTL`.
  - TS: `onPresence`, `presence()` and `presenceTtlMs`.
  - (PR 1620)
- **Fan-out.** A page tool declared `FanOut: true` goes to every tab in its room that offers it and
  agreed to the caller, and answers with one `FanOutResult` per tab. `targets: {users: [...]}`
  narrows it.
  - Fan-out tools have to be read-only, and a call over 25 tabs (`WithFanOutLimit`) is refused rather
    than cut short.
  - `Bridge.Notify(ctx, Selector{Rooms, Users}, name, data)` sends the host's own pages a
    notification with no agent involved, handled by `OnNotify` (Go) and `onNotify` (TS).
  - The dialled massrelay transport paces each connection at 25 messages a second. The relay
    silently drops anything past 30 a second, which would have lost tabs on a big fan-out.
  - (PR 1622)
- **A dynamic catalog for stateless callers.** `WithDynamicCatalogTTL(ttl)` serves a bridge with no
  `WithPageTools` to callers with no session. They see the tools of pages that agreed to them, with
  `cacheScope: private`. `WithScopeFilteredList()` shows each caller only the bridge tools its
  scopes allow, on both wires, and `list_pages` reports what was hidden as `stepUp`. Both are off by
  default. (PR 1623)

## Upgrading downstream

- **agni**:
  - Go: `experimental/ext/rooms`, `…/rooms/massrelay` and `…/integrations/roomsevents` at `v0.8.8`.
  - Browser: `@panyam/mcpkit-rooms@0.8.8`.
  - Nothing breaks. Presence, fan-out and the dynamic catalog are there to adopt when you want them.
- **Anyone who built `mcpskills`, `events-bridge` or `rooms-channel` from a checkout**: you can use
  `go install …@v0.8.8` instead.
- **Anyone filtering lists in middleware on a stateless server**: the filter now applies there too,
  which is what it always looked like it did.

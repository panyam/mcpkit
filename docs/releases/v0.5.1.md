# v0.5.1

A security patch. Three dependencies carrying published advisories are moved to
fixed versions. No API changes, no protocol changes, no behavior changes.

Two of the three were found by an external scan rather than by mcpkit's own CI.
The reason is worth recording, because it is a property of the tooling rather
than a lapse: `govulncheck` in its default mode answers "does this code call a
vulnerable symbol", and stays silent when the answer is no. That is the right
low-noise default for a release gate, and `.github/workflows/vulncheck.yml` was
working correctly. It is also why a stale indirect dependency can sit in the
tree with no local signal.

Verified against `ext/auth` pinned back to `golang.org/x/crypto v0.51.0`:

```
No vulnerabilities found.
This scan also found 0 vulnerabilities in packages you import and 14
vulnerabilities in modules you require, but your code doesn't appear to call
these vulnerabilities.
```

Exit code 0. The same tree under `govulncheck -scan module` reports the three
advisories below and exits 2.

## Fixed

- **`golang.org/x/crypto` v0.51.0 to v0.52.0** across all 16 modules that
  require it. Clears GO-2026-5021 (auth bypass via unenforced `@revoked` status
  in `ssh/knownhosts`), GO-2026-5023 (permission-enforcement skip in
  `VerifiedPublicKeyCallback`), and GO-2026-5033 (client panic on pathological
  input in `ssh/agent`). The dependency is indirect in every module and none of
  the affected symbols are reachable from mcpkit code, so this is a supply-chain
  hygiene bump rather than a fix for an exploitable path in mcpkit itself.

  All 16 modules move in lock-step, per `DEPENDENCY_POLICY.md`.
  `make check-dep-consistency` passes with a single version across the tree.

- **`vitest` 2.1.9 to 3.2.6** in the three development trees that were still on
  the `^2.0.0` range: `conformance/`, `tools/compat-reports`, and
  `tools/conformance-report`. `ext/ui/assets` and `agent/surfaces/web/web` were
  already on 4.x and are unchanged. These are test-runner trees, not shipped
  artifacts.

- **`hono` 4.12.14 to 4.13.1** in `examples/tasks/package-lock.json`. This is a
  transitive peer dependency of `@hono/node-server`, so only the lockfile
  changes; `package.json` is untouched. The advisory range is `hono <=4.12.33`
  and covers 18 advisories, so the fix line is above the 4.12 series.

## Known residual

- **GO-2026-5932** on `golang.org/x/crypto` has no fixed version published. It
  is the notice that `golang.org/x/crypto/openpgp` is unmaintained. mcpkit does
  not import that package. It will keep appearing in any version-matching
  scanner until the module drops it, so it needs a suppression entry rather
  than an upgrade.

- **`@hono/node-server` <2.0.5** (GHSA-frvp-7c67-39w9, path traversal in
  `serve-static` on Windows) remains in `examples/tasks`. It is pinned by
  `@modelcontextprotocol/node` at `^1.19.9` and npm reports no fix available.
  Forcing 2.x would be a major bump across an upstream SDK. mcpkit does not use
  `serve-static`, and the example is a demo rather than a published artifact.

## Not included

A repo-wide scan run while preparing this release surfaced further advisories
outside the reported scope. They are deliberately not bundled into a security
patch:

- `golang.org/x/net` v0.55.0 to v0.56.0 (GO-2026-5942)
- `github.com/yuin/goldmark` 1.7.13 to 1.7.17 (GO-2026-5320)
- `pillow` 12.2.0 to 12.3.0 in `uv.lock`, carrying 26 advisories. Nothing was
  scanning the Python tree.
- npm advisories in `examples/apps/react`, `ext/ui/assets`, and
  `ext/ui/tests/playwright` (`vite`, `postcss`, `esbuild`, `brace-expansion`,
  `fast-uri`, `@babel/core`).

These belong in the next dependency sweep, alongside adding a version-matching
scanner to complement the reachability one.

## Upgrading

No action required beyond the version bump. Nothing in the public API moved.

# v0.7.2

A patch release whose main fix is stdio. MCP's stdio transport is one JSON
message per line, and mcpkit spoke LSP-style `Content-Length` framing, so an
mcpkit stdio server never answered Claude Code, Cursor, or the Python and
TypeScript SDKs. Our own stdio tests always paired an mcpkit client with an
mcpkit server, which is why nobody noticed. That is fixed, along with a missing
protocol version and three protocol surfaces brought up to their current
specs. Some of the changes are wire-breaking, which `RELEASING.md` allows
before 1.0. The upgrade notes below list each one.

## Upgrading

- **stdio clients talking to an older mcpkit server** need
  `client.WithStdioFraming(client.FramingContentLength)` (or
  `client.WithCommandFraming` on a `CommandTransport`). The server side needs
  nothing: it detects the framing from the first byte it reads.
- **Events error codes** moved from `-32011..-32015` to `-32023..-32027`.
  Code comparing against `events.ErrCode*` is unaffected. Clients matching
  the literal numbers are not.
- **`experimental/ext/agents`** changed shape throughout. `AgentDef.Tools` is
  now `[]string`, results are flat, and four fields are gone. See the Changed
  section.
- **`server/stateless`**: `SubscribeFilter` is gone (use
  `core.SubscriptionFilter`), and `NewAcknowledgedFrame` / `NewTaggedFrame`
  take the id as `json.RawMessage`. Nothing outside mcpkit used them as far
  as we know.

## Fixed

- **stdio uses newline-delimited framing.** The server reads the client's
  first byte (`{` or `[` means newline-delimited, anything else
  `Content-Length`) and answers in kind for the session, so older mcpkit
  clients keep working. `server.WithStdioFraming` pins it instead. The client
  defaults to newline-delimited. (PR 1521, #1517)

- **Protocol version `2025-06-18` is supported.** It was missing from the
  supported list, although #57 was closed as having added it. A client pinned
  to it was negotiated up to `2026-07-28` and then failed every call for
  missing `_meta`, and a Streamable HTTP client sending it in
  `MCP-Protocol-Version` got a 400. (PR 1521, #1519)

- **Typed notification params reach `subscriptions/listen` streams intact.**
  A struct passed to `Broadcast` was nested under `"data"` on the frame, and
  any `_meta` it carried, a `traceparent` say, was dropped. (PR 1524)

## Changed

- **JSON-RPC batches are refused on 2025-06-18 and later.** 2025-03-26 added
  batching and 2025-06-18 removed it, but both HTTP transports accepted arrays
  on every version. Streamable HTTP now answers 400 with one `-32600`, and the
  legacy SSE transport pushes the same error on its stream. Nothing in a
  refused batch runs. (PR 1521)

- **`subscriptions/listen` follows the 2026-07-28 schema.** The
  `subscriptionId` is the JSON-RPC id of the listen request, where mcpkit used
  to mint its own. The acknowledgement now lists the filter keys the server
  will honor in `params.notifications`, and `notifications` is required. A
  base key such as `promptsListChanged` is honored only when the server
  advertises that `listChanged` capability. The upstream conformance suite
  grades none of this, which is how it slipped. (PR 1524, #1504)

- **`experimental/ext/agents` follows the Agent Discovery SEP**
  (agents-wg#22 at `9b16840e`). `agents/list` returns cards
  (`name`, `description`, `capabilities`) and can be paged, and
  `agents/get {name}` returns a flat result with `instructions`, an optional
  `modelRoutingHint` and the agent's tools. Both carry `resultType`, `ttlMs`
  and `cacheScope`, which defaults to `private`. An unknown or hidden agent is
  `-32602` with `data.reason: agent_not_found`, and an agent naming a tool the
  server lacks is `-32603` with `invalid_agent_definition`.
  `AgentDef.Tools` is a list of names looked up per request, so each tool
  matches the caller's `tools/list` entry, including the `x-mcp-file` strip
  for clients without `fileInputs`. `Config.Visible` hides agents per caller.
  `delegateTool`, `exampleTasks`, `tasksEnabled` and `skillUri` are gone.
  The Go client gained `ListAgentsPage`, a paging `ListAgents`, and the
  `IsAgentNotFound` / `IsInvalidAgentDefinition` classifiers. (PR 1516)

- **Events error codes follow SEP-3415**, `-32023..-32027` in place of
  `-32011..-32015`. The old numbers sit in the range the core specification
  leaves to implementations. (PR 1518, #1501)

## Added

- **Extensions can define `subscriptions/listen` filter keys.**
  `Server.RegisterSubscriptionFilter` takes a key and an `Accept` hook that
  sees the raw value and the request context. It can honor the key (returning
  what to echo and a matcher for broadcasts), decline it, or refuse the whole
  request, and a `*core.MissingCapabilityError` refusal becomes `-32021`.
  `server.ListChangedFilterKey` covers the boolean case:

  ```go
  srv.RegisterSubscriptionFilter(server.ListChangedFilterKey(
      "eventsListChanged", "notifications/events/list_changed"))
  ```

  Until now the filter was a closed struct, so no extension notification
  could reach a stateless listener at all. (PR 1524)

- **`Client.Listen`** opens one `subscriptions/listen` stream for every key a
  host wants, returns once the server acknowledges it, and routes
  notifications by method:

  ```go
  l, err := c.Listen(ctx, client.ListenOptions{
      Notifications: core.ListChangedFilter("toolsListChanged"),
      Handlers: map[string]func(json.RawMessage){
          "notifications/tools/list_changed": func(json.RawMessage) { refresh() },
      },
  })
  ```

  (PR 1524)

- **Events: `Config.ChatGPTCompat`** declares the capability at top-level
  `capabilities.events` as well, which is where ChatGPT reads it. SEP-3415
  puts it under `capabilities.extensions`, so it is off by default and its
  removal is tracked in #1511. The final `events/stream` result now carries
  the subscription ID in `_meta`. (PR 1518)

- **Events Go client: `Stream` reconnects a silent stream.** It measures the
  heartbeat interval from what it sees, and after twice that much silence, or
  a transport drop it did not ask for, it reopens the call with the last
  cursor. `StreamOptions.DisableReconnect` keeps the old single call. The
  client also gained a poll loop and a driver for the client conformance
  scenarios. (PR 1528, PR 1493)

## Tooling

- `make exercise-events` runs both events conformance suites into one table,
  and `make conf-events-setup` creates the checkouts they need. (PR 1512)
- Every conformance suite that starts its own server refuses to grade when the
  port was already held or the server died during startup, since a leftover
  process once got graded in its place. (PR 1514)
- The events suites quote SEP-3415 rather than the design sketch. (PR 1509,
  PR 1530)
